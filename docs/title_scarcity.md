数量金字塔为 `50 > 30 > 20 > 7 > 4`；概率金字塔为 `60% > 28% > 9% > 3% > 0`。UR 只通过合成获得。

## 2. 分级优先级

v4 不再把“获取人数少”直接等同于“称号等级高”。判断顺序如下：

1. **名字能否承载等级**：UR 必须具有跨场景的终局感；SSR 必须能代表一条完整路线。
2. **意义是否形成上下级**：SSR 与 SR 必须能回到同一主题，并存在可解释的门槛递进。
3. **实际门槛是否足够**：优先使用名次、累计数量、连续天数等明确条件。
4. **稀缺值是否支持**：获取次数只用于同等候选间排序，不能推翻前三项。

因此，获取次数少但含义较窄的 `铜笔杆` 属于创作路线 SR；获取次数较多但含义能统领“坚持与成长”的 `浴火重生` 属于 UR。

## 3. 上层结构

- **UR 4 个**：破界者、海纳百川、浴火重生、领袖。
- **SSR 7 个**：金笔杆、非凡贡献者、解题家、共情者、虔行者、元气满满、远见者。
- **SR 20 个**：全部来自现有徽章，分别归入创作、开源、解惑、共鸣、坚守、焕新、远见七条路线。
- **R 30 个**：从现有徽章中补足，负责普通池中层，不强行挂入上层路线。
- **N 50 个**：固定种子的自建称号，负责普通池底层和熔炼材料。

详细路线与名单见 `title_pool.md`；机器可读数据见 `title_pool.csv`。

## 4. 现有徽章的稀缺值

```text
S = max(1, round(100 × (1 − log10(grant_count + 1) / log10(154996))))
```

- 只用于现有徽章的辅助排序和展示；自建 N 不计算。
- `154996` 是当前最大获取次数 + 1；更换数据快照后重新计算。
- 分数越高表示获取人数越少；100 分只表示快照中获取次数为 0，不自动等于 UR。

## 5. UR 合成与消耗

| UR | 消耗的 3 张 SSR |
|---|---|
| 破界者 | 金笔杆 + 非凡贡献者 + 远见者 |
| 海纳百川 | 金笔杆 + 解题家 + 共情者 |
| 浴火重生 | 共情者 + 虔行者 + 元气满满 |
| 领袖 | 非凡贡献者 + 解题家 + 虔行者 |

完成 4 个 UR 共消耗 12 张 SSR：5 种共享 SSR 各 2 张，2 种独特 SSR 各 1 张。按 7 种 SSR 等权、综合 SSR 概率约 3.3% 估算，纯随机满足全部指定数量约需 **830 抽**；定向熔炼可补齐缺口。这里计算的是材料消耗模型，不是“集齐 7 种后永久解锁”。

## 6. 校准与风险

- 新增或替换 UR 时，必须重新检查四个 UR 能否覆盖七条路线，不能只换名字不改配方。
- 新增 SSR 时，必须同时给出路线、下属 SR 和参与的 UR；没有上下游关系的 SSR 不进入首发池。
- SR 至少应有活动名次、累计数量、连续天数或等价门槛；单次基础行为默认留在 R。
- 数据源 linux.do 的 `/badges*` 可能触发 Cloudflare 挑战；抓取失败时不要用旧数据静默覆盖。
- 概率、数量和稀缺值变化不会自动改变语义分级；任何换档都需要人工复核名字和描述。
